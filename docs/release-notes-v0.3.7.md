# Collect I18n v0.3.7

此版本根据 1000 词条 OMS 真实应用的采集运行数据（web-history 与 hash 路由两轮验证），修复 Agent 锚点选择、运行时定位器兼容与浏览器崩溃恢复问题，目标是“准确率优先、执行效率次之”：同等预算下减少零产出时间、提升覆盖率。

## 改进

- **浏览器崩溃自愈**：Playwright 持久化上下文因重负载/强退崩溃（`browser has been closed`）时，引擎自动重启浏览器配置文件并重试一次，不再让一次崩溃毒化整个采集会话；服务侧所有浏览器操作统一经健康检查 + 崩溃重试包装。
- **执行超时安全恢复**：TriggerPlan 超过 90s 执行时限后仅关闭失效页面并创建新页，浏览器保持存活，计划可重试（实测 `/orders` 计划第 1 次超时后第 2 次精简重试成功 +27 键）。
- **Agent 队列排除零 occurrence 锚点**：`agent next` 不再把源码零引用的词条（如 `dashboard.chart.*`、`advanced.result.*` 等）下发给 Agent，直接留给 `finalize` 的 `skippedNoSource`，消除每次约 2~4 分钟的必然失败执行。
- **Agent 队列静态锚点优先**：仅以动态插值匹配（`t(\`dashboard.${...}\`)`）的键在队列中降级，静态字面量锚点处理完之前不再消耗 Agent 执行；实测 dashboard 伪影键由上一轮 20 次双尝试降为 0 次。
- **路由批量饱和检测**：引擎按路由记录连续低产出轮次，连续两次新增捕获 ≈ 0 后，`agent next` 自动跳过该路由、切换到下一个未饱和路由。
- **交互高扇出路由优先**：路由排序加入交互潜力分（动作提示、命令式服务调用），分页/表单/弹窗类路由优先于纯静态路由。
- **弹窗定位器消歧**：多个控件同名且模态弹窗打开时，点击优先落在弹窗内（如 ElMessageBox 确认按钮 vs 表格行按钮语义冲突）。
- **定位器兼容运行时不透明标记**：构造 role/text/label 定位器时剥离或容忍 U+2060~U+2063 标记字符，修复 `getByRole(..., { name })` 精确匹配与 `exact: true` 文本匹配超时。
- **弹层/消息框点击可靠性**：点击前等待可见，超时后 `force` 兜底；自定义下拉框打开与选项匹配同步兼容标记。

## 修复

- `ElMessageBox`/Teleport 动画导致的确认按钮短暂不可见点击超时。
- 运行时标记污染 accessible name 导致角色定位器找不到目标。
- `agent execute` 失败路径未记录路由捕获统计，导致“失败计划”无法让路由饱和。

## 验证（hash 路由 + 清缓存，1000 词条 OMS 真实应用）

- 上一轮旧引擎：captured 367 / needs_manual 478 / skipped 155（Agent 阶段因浏览器崩溃仅 63 键）。
- 本轮新引擎：**captured 424 / needs_manual 421 / skipped 155，failed=0，duplicateEvidenceCount=0**（Agent 阶段 92 键，全程无浏览器卡死）。
- 同口径覆盖率 36.7% → 42.4%；详见 [v0.3.7-r2 性能分析](docs/performance-analysis-oms-app-v037-r2.md)。
