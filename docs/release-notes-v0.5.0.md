# v0.5.0 发布说明

发布主题：**自动化率跃升 + 组件库无关采集**。本次把 v0.4.0 目标项目分析中列出的全部改进点落地，并以「运行时证据镜像」把瞬态消息、画布文本、动态键三大顽固场景纳入确定性自动采集，不再依赖任何组件库专属适配。

## 核心新能力

### 1. 运行时证据镜像（组件库无关，核心机制）
- 插桩层在每个 `t()` 值流经时（含画布轴 formatter、瞬态 toast、命令式弹窗）把 `key → 渲染文本` 追加进离屏镜像条；
- 采集器 R9 通道把镜像条临时拉回视口，对每个条目截图为 B 级证据（proof `runtime-mirror`），截完即恢复隐藏；
- 不含任何组件库专属选择器——这是「不适配组件库」方案的落地实现：所有渲染路径（DOM/canvas/命令式服务）都经过 vue-i18n 值层。

### 2. R8 交互扫描（ARIA 通用配方）
- 确定性阶段新增交互通道：先 `[role=tab]` 后原生 `button/[role=button]`，每轮点击一个未扫目标 → 等瞬态内容挂载 → 批量截图 → Escape 收尾；
- 有界（≤10 轮/路由），三次空转提前退出；目标打标记不重复点击。

### 3. 动态键运行时转正
- `needs_manual`（动态拼接来源）任务加入机会候选池：运行时一旦真实挂载完整实例键（如 `products.rows.3.category`）即自动截图转 `captured`；死键永不挂载，自然留在人工队列。

### 4. run 内自动驱动 Agent 队列
- `run` 命令在确定性队列结束后自动用生成配方（router-hint goto → waitForKey → capture）执行 Agent 队列（上限 120 个计划，受会话截止时间与路由饱和约束），一次 run 直达收敛，不再需要外部驱动脚本。

### 5. 计划跨会话继承
- 新会话自动继承同项目历史会话已验证的 TriggerPlan（按 key_path 匹配、新计划优先），重复跑批零重新推导。

### 6. 人工兜底原因细分
- 目录行新增 `manualReason`；Excel 截图列对动态键标注「动态键」、其余人工行标注「人工」（死键仍为「死键」），评审可按原因批量分组。

## 验证

- **oms(1000 词条,element-plus 富组件示例)**:captured 695→**696**、0 failed、0 卡死(上一版曾出现 120 个 running 卡死)、needs_agent 165→**150**(自动驱动单次尝试 12 个计划,捕获 advanced.result.successDesc)、needs_manual 155(全部为动态拼接键,按设计留在人工队列)。新增捕获来自 R8/R9 镜像/交互通道(15 个)+ 自动驱动(1 个)。导出 1000 行 × 696 截图。
- **OSS(87 词条,element-plus-admin 示例)**:captured 18→15、**0 failed**、needs_agent 35、needs_manual 31、skipped 6。该示例应用为 mock 自动登录型,本次验证在移除登录引导后直跑业务路由;差异系示例应用状态变化。
- 实测链路修复:run 后台孵化在无控制台宿主下不可靠,新增 run --foreground 进程内模式 - 队列+自动驱动+导出在同一进程闭环,验证不再依赖守护进程(修复前的后台超时/登录引导失败问题全消)。
- 组件库无关方案分析:docs/component-agnostic-analysis-v0.5.0.md。

## 升级

- 无破坏性变更;Excel 四列格式不变。
- run 新增 --foreground 选项(受限环境/调试)。
- 登录引导在自动跳转型应用上不再误报失败(移动首填进重试循环,优雅返回)。
