# v0.3.18 发布说明

确定性采集的第五轮改进:R7 控件扫描——分页表格尾页行词条与折叠树叶子不再依赖 Agent 计划即可被确定性采集。

## R7 确定性控件扫描

- 新增 `widgetSweepForCapture`:每轮有界点击**纯客户端控件**——Element Plus 树展开图标(`.el-tree-node__expand-icon:not(.is-leaf)`,跳过已展开)与分页「下一页」按钮(`.el-pagination .btn-next`,跳过禁用态)。每轮至多 6 次点击、每路由至多 8 轮;**从不触碰表单、向导或任何动作按钮**,扫描不可能变更项目数据。
- 每轮点击后等待 loading 遮罩清除(F1-F5 机制)再检视+批采,与 R3 滚屏同一契约:仅在仍有未处理候选时运行,扫描穷尽即停。
- 此前 oms 分页表格第 2/3 页的行词条(每页 40-60 键)只能靠 Agent 计划逐页点击采集;现确定性阶段即可直达。

## 其他

- 路由访问流在 R3 滚屏之后挂接 R7;两者共用批采、预算与 loading 等待机制。
- 文档:`docs/cli-reference.md` 与 `skill/collect-i18n/SKILL.md` 补充 R3/R7 有界展开通路说明。

## 实测(oms-complex-app,v0.3.18 引擎)

- **纯确定性 captured 670/1000(67%)**——同一路由集合在 v0.3.17(无 R7)纯确定性仅 375(37.5%),而 v0.3.16 时代靠 8-10 个 Agent 计划也只有 550(55%):分页与树展开把约 **295 个键**从 Agent/人工队列拉回确定性采集,`needs_agent` 从 470 降至 175(收拢后 manual 仅剩级联/日期等更深控件键)。
- 端到端:`run` 30 分钟窗口排空 1000 键队列,failed 0,工作簿 1000 行/**670 图**导出;155 死键照常标注「死键」置底。
- 门禁:typecheck 11 包通过、测试 **177/177**、e2e **2/2**(真实 Chrome)、lint:version 0.3.18 一致。
