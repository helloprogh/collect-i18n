# collect-i18n v0.3.15 发布说明

## 非可视词条导出标注(截图列=非可视)

在 v0.3.14 废弃置底功能基础上扩展导出标注,让审阅者一眼区分两类不可截图词条:

- **废弃词条**(`no_source_occurrence`)维持原行为:集中排在工作表末尾,截图列填写「词条废弃」。
- **非可视词条**(`non_visual_source_only`,所有 occurrence 都是 `aria-*`/原生元素 `title`)新增标注:保持字母序原位,截图列填写「非可视」(灰色斜体居中,样式与废弃行一致);不置底、不断言废弃。
- `localeCatalog` 同步返回 `deprecated`/`nonVisual` 标记;修复会话创建时预分类的 `skipped` 任务未持久化 `skip_reason` 的问题(此前只有 `finalize` 会写入该原因,导致预分类死键/非可视键在导出中永远拿不到标注)。

## 确定性采集吞吐改进(R1-R6)

本轮将确定性窗口的预算集中在「词条密集的路由」上,并用批量采集替代逐键等待,显著降低未采集词条与 Agent 队列压力:

- **R1 路由密度排序**:按每条路由待处理 `pending` 词条数降序访问(取代字母序),零产出路由下一轮跳过;全部路由零产出的整轮扫描防御性终止。
- **R2 路由内批量采集**:单次页面求值 + 单次截图标记通道完成同路由所有已挂载键的解析与截图(上限 250 键/批),取代逐键 `waitForKey` + 稳定性采样循环。
- **R3 有界滚动采集**:对未处理键做有界滚动步进(80% 视口/末步到底),让懒加载与虚拟列表行挂载后再次批量采集;逐键兜底设每路由 12 次预算,超出预算的键保持 `pending` 留待下一轮,避免在窗口内空转。
- **R4 批量因果 canary**:一次隔离探针页导航(occurrenceId→token 映射)即可验证同路由多个 B 级 Vue 证据,消除每个键单独 `newPage`+重放的开销。
- **R5 Agent 计划同路由页面复用**:当前页已展示计划路由时跳过整页导航(Vite 重建+路由稳定,每计划数秒),直接复用页面执行计划。
- **R6 提前结束语义**:确定性窗口未耗尽但队列已无产出时结束窗口,剩余键保持 `pending` 并返回 `nextAction=deterministic_continue`,指引继续轮询同一会话直至 `pending`/`running` 归零;`--deterministic-timeout-minutes` 默认值随词条数自适应为 `max(15, ceil(total/60))`。

## 真实项目实测(translation-lab,1000 词条)

v0.3.15 引擎在 `examples/vue-i18n-translation-lab`(1000 词条)完成一轮长窗口 + 多路由 Agent 计划 + finalize + export 的完整驱动:

- **最终覆盖率 83.4%**(captured 834/1000);`needs_manual` 153(全部为死键)、`skipped` 13、`failed` 0、`pending`/`running` 归零,`exportReady` 就绪。
- **确定性阶段(R1-R3)**:22 分钟内将 645 个 `pending` 全部排出并采集(captured 142→366),批量采集 + 滚屏 + 逐键兜底预算共同生效。
- **Agent 阶段(R4-R5)**:12 个路由计划(11 全成功 + 1 部分成功)净增 468 键,平均约 37 键/计划、18+ keys/min——对比研究基线平均 1.94 键/计划,**吞吐约 9.5x**;饱和路由硬排除与每路由锚点预算生效,无低产重复空转。
- **导出标注**:工作簿 1000 行/834 张截图,废弃与非可视词条分别以「词条废弃」(置底)/「非可视」(原位)标注。
