# Collect I18n v0.3.1

此版本修复 Agent 调用环境中采集服务被中断、重复执行者误停其他会话时的恢复与隔离问题。

## 修复

- 新增 `start --session <id>`，在不改变任务 ID、计划和证据归属的前提下恢复 `stopped`/`interrupted` 会话。
- 确定性采集被停止时，尚未完成的任务重新进入 `pending`，不再错误降级为 Agent 任务。
- `agent execute` 与 `manual open` 在没有其他活动服务时自动恢复自己的会话；若另一会话正在运行则拒绝劫持。
- `run` 在服务中断且仍有未完成任务时返回 `nextAction: restart`，避免把基础设施中断误报为 Agent 工作。
- `stop --session <id>` 只停止匹配会话，避免并行或遗留 Agent 终止当前有效工作流。

## Skill 协议

- `run` 使用足够长的调用超时。
- 恢复必须携带原始 `sessionId`，禁止用无参数 `start` 创建新会话替代恢复。
- 遇到活动会话时优先复用或报告冲突，不再为“重新开始”自动停止它。

## 验证

- 全仓类型检查、100 项测试、601 词条基准检查、示例项目构建与 Skill 打包校验通过。
- 在全新真实项目中使用 Claude Code `glm-5.2` 和发布 ZIP 完成 601 词条自动阶段：142 张确定性截图、0 失败，随后 Agent 覆盖 Element Plus Prompt、业务接口错误、懒加载、Teleport、订单操作等场景。
- 首版 Excel 为 601 行、严格四列、142 张图片；图片锚点与导出时刻的 142 个证据 Key 一一对应。
- Agent 续跑在 207 张截图、2 个人工项时因模型 5 小时配额耗尽中止；会话通过 `stop --session` 安全保存，可在配额恢复后继续，未将剩余任务记为通过。
